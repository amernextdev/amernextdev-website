# glossary.md

## الهدف
تعريف المصطلحات المتخصصة المستخدمة عبر وثائق المنظومة — استراتيجية، تقنية، وتشغيلية.
المرجع عند أي غموض في معنى مصطلح في أي وثيقة أخرى.

## المشمول
- مصطلحات الاستراتيجية والتموضع
- مصطلحات التقنية والهندسة
- مصطلحات التشغيل والحوكمة
- اختصارات متكررة

## غير المشمول
- شرح المفاهيم بعمق (كل مصطلح يُحيل لوثيقته)
- مصطلحات تقنية عامة غير مخصصة للمنظومة (React، TypeScript — هذه موثقة خارجياً)

## أ — مصطلحات الاستراتيجية والتموضع

**آلية التصفية (Filter Mechanism)**
عنصر تصميمي أو محتوى مُصمَّم لطرد الآفاق غير المؤهلة قبل أي تواصل.
← `trust-filter-framework.md`

**المقيّم (Evaluator)**
الشخص الذي يصل للموقع ويُقيّم عامر كمرشح. يختلف عن "المستخدم" — هو شخص يُجري تدقيقاً حقيقياً، لا تصفحاً عاماً.
← `client-psychology-model.md`

**المقيّم الأساسي**
صانع قرار يمتلك صلاحية الميزانية والإلمام التقني ومشكلة على مستوى الأنظمة.
← `client-psychology-model.md`

**المقيّم الثانوي**
حارس تقني (CTO، مهندس رئيسي) يفحص الكود ويُشترط موافقته.
← `client-psychology-model.md`

**البصمة المعرفية (Cognitive Fingerprint)**
الانطباعات الخمس التي يجب أن تترسخ في ذاكرة المقيّم: منضبط، دقيق، تقني، انتقائي، واثق.
← `brand-cognitive-model.md`

**التمايز التصنيفي (Categorical Differentiation)**
تغيير معايير التقييم نفسها، لا مجرد التفوق على المنافسين في نفس المعايير.
← `anti-portfolio-manifesto.md`

**التموضع (Positioning)**
كيف يُدرَك عامر في ذهن المقيّم — ليس ما يُقال بل ما يُبنى.
← `positioning-doctrine.md`

**نزاهة التموضع (Positioning Integrity)**
الحفاظ على التمايز التصنيفي دون خفضه مقابل ثراء الميزات أو الجاذبية الجماهيرية.
← `master-constitution.md`، `decision-engine.md`

**نمط التدقيق المكثف (Deep Due Diligence Pattern)**
نمط القرار الذي يتبعه المقيّم المستهدف — تحديد مشكلة، بحث عن مرشح، تدقيق فعلي، قرار تواصل. يختلف جوهرياً عن نمط الشراء الاستهلاكي.
← `client-psychology-model.md`

**وكيل السلطة (Authority Proxy)**
الموقع بديل عن التفاعل المهني المباشر — يؤدي وظيفة المصداقية ذاتها.
← `master-constitution.md`

## ب — مصطلحات التقنية والهندسة

**أمان الهجرة (Migration Safety)**
ضمان أن القرارات التقنية في المرحلة الحالية لا تُعيق الانتقال النظيف للمرحلة التالية.
← `technical-axioms.md`، `decision-engine.md` البوابة 2

**البديهية (Axiom)**
قيد تقني غير قابل للتفاوض يحكم جميع القرارات. يختلف عن التفضيل أو الأسلوب.
← `technical-axioms.md`

**التوكن / Design Token**
متغير CSS يُعبّر عن قيمة تصميمية دلالية (لون، حجم، تباعد). المصدر الوحيد للحقيقة للقيم البصرية.
← `css-design-tokens.md`

**الدين التقني (Technical Debt)**
قرار تقني يُسهّل الحاضر ويُكلّف المستقبل. مقبول إذا وُثِّق مع خطة سداد.
← `git-workflow.md`، `risk-landscape.md` R4

**عزل المكوّن (Component Isolation)**
معيار يضمن أن كل وحدة UI مكتفية ذاتياً وقابلة للاستخراج كـ React component.
← `component-isolation-standard.md`

**فصل المسؤوليات (Separation of Concerns)**
HTML للبنية، CSS للعرض، JS للسلوك. لا اقتران بين الطبقات.
← `technical-axioms.md` البديهية الثانية

**قابلية التجريد (Abstraction Readiness)**
بناء الكود بحيث يمكن استبدال التفاصيل (JSON → API، CSS → Design System) دون تغيير المنطق.
← `technical-axioms.md` البديهية الثالثة

**الوحدة (Module)**
ملف JS يُدير مسؤولية واحدة محددة. له واجهة عامة صريحة ويتواصل مع الوحدات الأخرى عبر events.
← `js-module-architecture.md`

## ج — مصطلحات التشغيل والحوكمة

**الانجراف (Drift)**
تراكم قرارات صغيرة تُحوّل المنظومة تدريجياً بعيداً عن مبادئها دون قرار واعٍ.
← `risk-landscape.md` R1، R3

**بروتوكول القرار (Decision Protocol)**
تسلسل البوابات الخمس التي يمر بها أي قرار تنفيذي قبل القبول.
← `decision-engine.md`

**حد المرحلة (Phase Boundary)**
نقطة اكتمال مرحلة تطور واستيفاء شروط الانتقال للمرحلة التالية.
← `evolution-matrix.md`

**القانون غير القابل للتفاوض (Non-Negotiable Law)**
قيد محلول مسبقاً لا يحتاج تداولاً عند نقطة القرار. أي مقترح يخالفه يُرفض فوراً.
← `non-negotiable-laws.md`

**المحتوى اليتيم (Orphan Content)**
قسم أو عنصر محتوى لا يُجيب على سؤال محدد للمقيّم.
← `risk-landscape.md` R7، `client-psychology-model.md`

**المنظومة (System)**
المشروع الكامل — الموقع، الوثائق، القرارات، والبنية التحتية — كوحدة متكاملة.
الكلمة تُستخدم عمداً بدل "الموقع" للتأكيد على البُعد الاستراتيجي.

**النمط المضاد (Anti-Pattern)**
وضع فشل مُسمَّى. التسمية تُتيح رفضاً أسرع عند نقطة القرار.
← `master-constitution.md` القسم العاشر، `risk-landscape.md`

**وضع الفشل (Failure Mode)**
سيناريو محتمل يُفسد نزاهة المنظومة أو أداءها. مُوثَّق مسبقاً مع إشارات كشف مبكر.
← `risk-landscape.md`
