# ✍️ دليل كتابة المحتوى | Content Writing Guide

## 🎯 الفلسفة الكتابية

### المبدأ الأساسي
> **"كل كلمة لها وظيفة. إذا لم يكن لها وظيفة، احذفها."**

### النبرة (Tone)

**ما هي النبرة المطلوبة؟**
- هادئة
- واثقة (بدون غرور)
- مباشرة (بدون خشونة)
- احترافية (بدون تعقيد)
- صادقة (بدون تواضع مبالغ فيه)

**ما هي النبرة المرفوضة؟**
- ❌ المبالغة التسويقية
- ❌ الادعاءات الكبيرة
- ❌ العاطفة الزائدة
- ❌ القصص الشخصية
- ❌ الوعود المبهرة

## 📏 القواعد الذهبية

### القاعدة 1: البساطة
```
✅ "أبني تطبيقات ويب موثوقة"
❌ "أقوم بتطوير حلول برمجية متكاملة ومبتكرة باستخدام أحدث التقنيات"
```

### القاعدة 2: التحديد
```
✅ "خبرة 5 سنوات في Full-Stack Development"
❌ "خبرة واسعة في مجال البرمجة"
```

### القاعدة 3: الصدق
```
✅ "أعمل على مشاريع متوسطة إلى كبيرة"
❌ "أستطيع بناء أي شيء!"
```

### القاعدة 4: الفائدة
```
✅ "أنظمة قابلة للتوسع تنمو مع عملك"
❌ "استخدم أحدث التقنيات"
```

### القاعدة 5: الإيجاز
```
✅ جملة واحدة قوية
❌ فقرة طويلة تقول نفس الشيء
```

## 🚫 الكلمات والعبارات الممنوعة

### ممنوع نهائيًا:
- ❌ "الأفضل"
- ❌ "الأقوى"
- ❌ "الأسرع"
- ❌ "الحل السحري"
- ❌ "نتائج مضمونة"
- ❌ "أي مشروع"
- ❌ "استثنائي"
- ❌ "مذهل"
- ❌ "رائع"

### استخدم بحذر شديد:
- ⚠️ "احترافي" (اُذكر مرة واحدة فقط)
- ⚠️ "خبير" (استبدلها بـ "خبرة X سنوات")
- ⚠️ "متخصص" (كن محددًا في ماذا)

### البدائل الأفضل:
```
بدلًا من: "حلول استثنائية"
استخدم: "حلول موثوقة"

بدلًا من: "أفضل مطوّر"
استخدم: "مطوّر Full-Stack بخبرة 5 سنوات"

بدلًا من: "نتائج مذهلة"
استخدم: "نتائج قابلة للقياس" أو لا تذكر شيئًا
```

## 📝 كتابة العناوين (Headlines)

### صيغة العنوان الرئيسي (H1)

**القالب:**
```
[الفعل] + [الشيء] + [الصفة الوظيفية]
```

**أمثلة جيدة:**
```
✅ "أبني أنظمة ويب موثوقة وقابلة للتوسع"
✅ "أطور تطبيقات ويب للشركات الجادة"
✅ "Full-Stack Developer متخصص في الحلول طويلة المدى"
```

**أمثلة سيئة:**
```
❌ "مرحبًا، أنا أحمد!"
❌ "مطوّر ويب محترف"
❌ "أفضل حلول البرمجة"
```

### صيغة العناوين الثانوية (H2)

**القالب:**
```
سؤال بسيط أو تصريح مباشر
```

**أمثلة:**
```
✅ "لماذا أعمل بطريقة مختلفة؟"
✅ "كيف أبني المشاريع؟"
✅ "الخدمات التي أقدمها"
✅ "ماذا يميز عملي؟"
```

## 📄 كتابة الأوصاف (Descriptions)

### الفقرات القصيرة

**القاعدة:** 2-3 أسطر كحد أقصى

**مثال جيد:**
```
أركز في عملي على فهم المشكلة قبل كتابة الكود. أبني أنظمة 
مصممة للنمو، وليس فقط للإطلاق. كل مشروع يُعامل كاستثمار 
طويل المدى، وليس حلًا مؤقتًا.
```

**مثال سيء:**
```
أنا مطوّر Full-Stack بخبرة واسعة في مجال تطوير الويب. 
أعمل بشغف على تقديم أفضل الحلول التقنية المبتكرة لعملائي 
الكرام. أستخدم أحدث التقنيات والأدوات لضمان تقديم منتجات 
استثنائية تفوق التوقعات وتحقق النجاح الباهر...
```

### الأوصاف التقنية

**القاعدة:** ذكر التقنيات بدون مبالغة

**مثال جيد:**
```
التقنيات: React, Node.js, PostgreSQL
الهدف: تطبيق dashboard لإدارة العمليات
النتيجة: تقليل الوقت المستغرق بنسبة 40%
```

**مثال سيء:**
```
استخدمت أحدث وأقوى التقنيات المتاحة بما فيها React الثوري، 
Node.js القوي، وPostgreSQL الأكثر موثوقية لبناء تطبيق 
dashboard فائق السرعة يتميز بأداء استثنائي...
```

## 🎯 كتابة CTA (Call-to-Action)

### القواعد

1. **وضوح الفعل**
2. **لا ضغط**
3. **واقعية**

### أمثلة جيدة:
```
✅ "اعرف المزيد عن خدماتي"
✅ "شاهد أعمالي"
✅ "ابدأ المحادثة"
✅ "دعنا نناقش مشروعك"
```

### أمثلة سيئة:
```
❌ "احجز الآن قبل فوات الأوان!"
❌ "اتصل الآن وستحصل على خصم!"
❌ "لا تفوّت الفرصة!"
❌ "اشترك مجانًا!"
```

## 📋 كتابة القوائم

### متى تستخدم القوائم؟

**استخدمها فقط عند:**
- ✅ سرد خطوات عملية
- ✅ ذكر ميزات محددة
- ✅ تفصيل خدمات

**لا تستخدمها في:**
- ❌ النصوص التوضيحية العامة
- ❌ الفلسفة أو القيم (اكتبها نثرًا)

### تنسيق القائمة

**كل نقطة في القائمة:**
- 1-2 جملة كحد أقصى
- تبدأ بفعل أو اسم
- متوازنة مع باقي النقاط

**مثال جيد:**
```
كيف أعمل:
• الاكتشاف: فهم عميق للمشكلة والأهداف
• التخطيط: تصميم البنية قبل البرمجة
• التطوير: بناء تدريجي مع اختبارات مستمرة
• الإطلاق: نشر آمن مع متابعة أولية
```

**مثال سيء:**
```
كيف أعمل:
• أولًا، أقوم بعقد اجتماع مع العميل لفهم احتياجاته بشكل 
  كامل ومناقشة كل التفاصيل الدقيقة...
• بعد ذلك، أبدأ بالتخطيط المفصل...
```

## 💬 كتابة Case Studies

### البنية القياسية

```
1. نوع المشروع: [نوع واضح]
2. المشكلة: [1-2 جملة]
3. الحل: [2-3 جمل]
4. التقنيات: [قائمة بسيطة]
5. النتيجة: [أرقام إن وجدت، أو وصف موضوعي]
```

### مثال كامل:

```markdown
## تطبيق إدارة مشاريع للشركات

**نوع العميل:** شركة متوسطة في قطاع التكنولوجيا

**المشكلة:**
كانت الشركة تعتمد على جداول Excel وأدوات متفرقة لإدارة 
المشاريع، مما أدى إلى تشتت البيانات وصعوبة المتابعة.

**الحل:**
بنيت تطبيق ويب مركزي يجمع إدارة المهام، الوقت، والفريق 
في مكان واحد. ركزت على واجهة بسيطة لتقليل منحنى التعلم.

**التقنيات:**
React, Node.js, PostgreSQL, Docker

**النتيجة:**
- تقليل الوقت المستغرق في التنسيق بنسبة 35%
- تحسين شفافية المشاريع
- اعتماد كامل من الفريق خلال أسبوعين
```

**لاحظ:**
- ✅ لا ادعاءات مبالغ فيها
- ✅ أرقام حقيقية (إن وجدت)
- ✅ تركيز على القيمة وليس التقنية فقط
- ✅ وصف موضوعي

## 🔤 الأسلوب اللغوي

### استخدام الضمائر

**المفضّل:**
- أنا / أعمل / أبني
- نحن (إذا كنت تتحدث عن عملك مع فريق)

**تجنب:**
- نحن (وأنت وحدك)
- هو/هي (عن نفسك)

### المخاطبة

**مع الزائر:**
```
✅ "إذا كنت تبحث عن..."
✅ "هل لديك مشروع؟"
✅ "دعنا نتحدث"
```

**تجنب:**
```
❌ "سيدي العزيز"
❌ "عميلي الكريم"
```

### طول الجملة

**القاعدة:** 15-20 كلمة كحد أقصى

**إذا تجاوزت 20 كلمة:** قسّمها

**مثال:**
```
❌ سيء:
"أعمل على بناء تطبيقات ويب متكاملة للشركات التي تبحث 
عن حلول تقنية طويلة المدى وموثوقة وقابلة للتوسع."

✅ جيد:
"أبني تطبيقات ويب متكاملة. أركز على الحلول طويلة المدى 
التي تنمو مع عملك."
```

## 📊 الأرقام والإحصائيات

### متى تذكر أرقام؟

**استخدمها عند:**
- ✅ سنوات الخبرة (حقيقية)
- ✅ عدد المشاريع (حقيقي)
- ✅ نتائج قابلة للقياس (في Case Studies)

**لا تذكرها إذا:**
- ❌ غير دقيقة
- ❌ صغيرة جدًا (مثل "2 مشاريع فقط")
- ❌ مبالغ فيها

### تنسيق الأرقام

```
✅ "خبرة 5 سنوات"
❌ "خبرة خمس سنوات"

✅ "تحسين الأداء بنسبة 40%"
❌ "تحسين كبير في الأداء"
```

## 🎨 أمثلة كاملة لكل صفحة

### الصفحة الرئيسية - Hero Section

```markdown
# أبني أنظمة ويب موثوقة وقابلة للتوسع

للشركات التي تبحث عن حلول تقنية طويلة المدى، 
وليس مجرد تنفيذ سريع.

[اعرف المزيد عن خدماتي]
```

### صفحة الخدمات - مقدمة

```markdown
# الخدمات

أعمل مع الشركات لبناء تطبيقات ويب تخدم أهدافها الفعلية. 
أركز على الفهم قبل البرمجة، والجودة قبل السرعة.
```

### صفحة من أنا - مقدمة

```markdown
# من أنا

مطوّر Full-Stack بخبرة 5 سنوات في بناء تطبيقات ويب 
للشركات المتوسطة. أؤمن أن التكنولوجيا يجب أن تحل مشاكل 
حقيقية، وليس فقط أن تبدو جيدة.
```

### صفحة التواصل - مقدمة

```markdown
# تواصل معي

هل لديك مشروع؟ دعنا نتحدث عنه.

أعمل على مشاريع متوسطة إلى كبيرة تسمح بالتخطيط 
والتنفيذ السليم. املأ النموذج أدناه وسأرد خلال 24-48 ساعة.
```

## ✅ Checklist قبل النشر

لكل نص، اسأل نفسك:

- [ ] **هل هو واضح؟** (يفهمه أي شخص في 3 ثوانٍ)
- [ ] **هل هو صادق؟** (لا مبالغة، لا ادعاءات)
- [ ] **هل هو مختصر؟** (لا حشو، لا تكرار)
- [ ] **هل له وظيفة؟** (يوجه الزائر أو يبني ثقة)
- [ ] **هل يخدم الجمهور؟** (وليس الـ Ego)

**إذا كانت الإجابة "لا" على أي سؤال → أعد الكتابة.**

## 🎯 الخلاصة

**المحتوى الجيد:**
- ✅ بسيط لكن ليس سطحي
- ✅ واثق لكن ليس متعجرف
- ✅ مختصر لكن كامل
- ✅ صادق بدون تواضع مبالغ
- ✅ يخدم الزائر، لا الكاتب

**المبدأ النهائي:**
> "اكتب كأنك تتحدث مع عميل محتمل ذكي لا يحب المبالغة."
