# المهمة الأولى — النبرة والأسلوب الكتابي لكل صفحة

كل صفحة في الموقع هي وحدة تواصل مستقلة تخدم هدفاً محدداً في رحلة تقييم العميل. النبرة ليست اختياراً جمالياً — هي آلية تصفية. ما يلي مستخلص مباشرة من منطق الفصلين الثالث والرابع من الدستور.

---

## 1. صفحة Home — الرئيسية

| المحور | التفاصيل |
|--------|-----------|
| **النبرة العامة** | حازمة، صامتة، لا تستدعي — تُعلن ولا تطلب. |
| **الموقف العاطفي** | لا حرارة، لا برود. درجة الثقة بالذات: عالية جداً. درجة الحماس: صفر. درجة التودد: صفر. لا "يسعدني"، لا "أهلاً بك". |
| **نمط الجمل** | قصيرة جداً. موجزة. لا جمل مركبة في الـ Hero. الجملة الرئيسية ≤ 10 كلمات. لا شروح — تصريحات. |
| **الكلمات المحظورة** | "متاح"، "محترف"، "ذو خبرة"، "شغوف"، "أنا هنا لمساعدتك"، "دعنا نتحدث"، "أسعار تنافسية"، أي CTA مباشر. |

**مثال:**

| ✓ صواب | ✗ خطأ |
|--------|--------|
| *Systems engineer. Architectural discipline. No compromise on structure.* | *مرحباً! أنا عامر، مهندس برمجيات محترف وشغوف بتطوير الويب. أنا هنا لمساعدتك في مشروعك.* |

## 2. صفحة Work — الأعمال

| المحور | التفاصيل |
|--------|-----------|
| **النبرة العامة** | دليل لا عرض. حقائق معمارية لا صور جمالية. المشروع هو الدليل، الوصف هو التأطير. |
| **الموقف العاطفي** | محايد تماماً. لا فخر معلن، لا استعراض. الكفاءة تتكلم عبر التفاصيل التقنية. |
| **نمط الجمل** | متوسطة. جملة تصف المشكلة + جملة تصف القرار المعماري + نتيجة قابلة للقياس. لا استطرادات. |
| **الكلمات المحظورة** | "رائع"، "مبهر"، "أفضل عمل لي"، "أحب هذا المشروع"، أي تعليق عاطفي. لا "تصميم جميل". |

**مثال:**

| ✓ صواب | ✗ خطأ |
|--------|--------|
| *Migrated a monolithic Node.js API to a modular service layer, reducing cold-start latency by 60% and enabling isolated deployment per domain.* | *هذا مشروع رائع عملت عليه بجد كبير — موقع متجر إلكتروني جميل وسريع للغاية!* |

## 3. صفحة Case Study — دراسة الحالة

| المحور | التفاصيل |
|--------|-----------|
| **النبرة العامة** | تحليلية، وثائقية، منهجية. كاتب التقرير لا كاتب الإعلان. |
| **الموقف العاطفي** | موضوعي بالكامل. النص يصف القرارات والأسباب والنتائج — ليس المشاعر تجاه العمل. |
| **نمط الجمل** | أطول من بقية الصفحات — المحتوى يحتاج عمقاً. فقرات هرمية: مشكلة → قرار → السبب المعماري → نتيجة. لا تخطي الـ "لماذا". |
| **الكلمات المحظورة** | أي عبارة تسويقية. "نجحنا"، "أبهرنا العميل"، "حلول مبتكرة"، "تجاوزنا التوقعات". |

**مثال:**

| ✓ صواب | ✗ خطأ |
|--------|--------|
| *The authentication layer was refactored from session-based to JWT with refresh token rotation. This decision was driven by the requirement for stateless horizontal scaling across three deployment regions, not by a preference for JWTs as a pattern.* | *استخدمنا أحدث التقنيات وأبهرنا العميل بالنتيجة المذهلة التي تجاوزت كل التوقعات!* |

## 4. صفحة Approach — المنهجية

| المحور | التفاصيل |
|--------|-----------|
| **النبرة العامة** | تعليمية-بنيوية. تُعلن المبادئ لا تُشرح لتُقنع. ثقة المعلم لا لهجة المقاول. |
| **الموقف العاطفي** | واثق وغير مُلزم. القارئ مدعو للفهم — لا للإعجاب. لا استرهاب العميل، لا مغازلته. |
| **نمط الجمل** | متوسطة إلى طويلة نسبياً. يُسمح بالبنية المركبة هنا لأن الفكرة تحتاج بسطاً مبنياً. كل مبدأ له عنوانه. |
| **الكلمات المحظورة** | "نهج فريد من نوعه"، "نختلف عن الجميع"، "عميلنا في قلب عملنا"، أي شعارات تسويقية. |

**مثال:**

| ✓ صواب | ✗ خطأ |
|--------|--------|
| *Architecture decisions are made before the first line of code is written. Structure is not a byproduct of implementation — it is a precondition for it.* | *نتبع نهجاً فريداً وإبداعياً يضع العميل في قلب كل قرار نتخذه!* |

## 5. صفحة Contact — تواصل

| المحور | التفاصيل |
|--------|-----------|
| **النبرة العامة** | انتقائية، هادئة، غير متهالكة. الباب موجود — وليس مفتوحاً على مصراعيه. |
| **الموقف العاطفي** | لا إلحاح إطلاقاً. لا "لا تتردد في التواصل". الصفحة تُرشّح وتُصفّي — لا تستجدي. |

| **الكلمات المحظورة** | "يسعدني"، "لا تتردد"، "أنا متاح"، "أجيب خلال 24 ساعة"، "احصل على عرض مجاني". |

**مثال:**

| ✓ صواب | ✗ خطأ |
|--------|--------|
| *For principals with defined scope and a systems-level problem. Not accepting speculative requests or unstructured inquiries.* | *أنا هنا ومتاح دائماً، لا تتردد في التواصل معي في أي وقت وسيسعدني مساعدتك!* |

## 6. صفحة Notes — ملاحظات

| المحور | التفاصيل |
|--------|-----------|
| **النبرة العامة** | تأملية، نقدية، عمودية-فكرية. هذه هي الصفحة الوحيدة التي تتوسع فيها الشخصية. |
| **الموقف العاطفي** | ذكي بلا تعالٍ، نقدي بلا مرارة، واضح بلا بساطة. يُسمح بنبرة شخصية محسوبة هنا فقط. |
| **نمط الجمل** | أحرار أكثر — يُسمح بالجمل المركبة والاستطراد المقصود. لكن لا ترهل، لا حشو، لا استعراض حجم. |
| **الكلمات المحظورة** | "في رأيي المتواضع"، "ربما أكون مخطئاً"، أي تلطيف مفرط للرأي. لا تلقيح مصطنع للتواضع. |

**مثال:**

| ✓ صواب | ✗ خطأ |
|--------|--------|
| *The framework is not the architecture. The architecture is the arrangement of concerns. A well-structured jQuery project outperforms a poorly structured React codebase in every metric that matters.* | *في رأيي المتواضع، وربما أكون مخطئاً، أحياناً أعتقد أن الأُطر البرمجية قد تكون مشكلة بعض الشيء.* |

# المهمة الثانية — قواعد الكتابة العامة للموقع كله

---

## أولاً: قواعد الصوت

> مستخلصة من القسم `12.3` من الدستور — Language Governance.

| القاعدة | التطبيق العملي |
|---------|----------------|
| **أول شخص + صوت نشط** | `"I build systems"` لا `"Systems are built by me"`. الفاعل دائماً حاضر. الجملة الإنجليزية تبدأ بـ `I` / `The system` / `This layer` — لا بـ `was`. |
| **لا superlatives** | `"Experienced"` لا `"Highly experienced"`. `"Delivered"` لا `"Successfully delivered"`. لا كلمة تزيد الفعل أو الصفة — الفعل يكفي وحده. |
| **لا تضخيم حماس** | الإجراءات الاحترافية لا تتضمن تعبيرات الفرح أو الشغف. `"I enjoy working on complex systems"` مقبول. `"I'm passionate about transforming your vision!"` محظور تماماً. |
| **لغة المجال مسموحة ومفضلة** | الجمهور متعلم تقنياً. `"Modular React component architecture"` أفضل من `"أبني تطبيقات حديثة"`. التبسيط الزائد يُفسد التموضع. |

---

## ثانياً: قواعد الدقة اللغوية

| القاعدة | التفسير |
|---------|---------|
| **لا صفات مبهمة** | `"Clean, scalable architecture"` — لكن ماذا يعني scalable تحديداً؟ أضف: `"deployable across N instances without configuration changes"`. الصفة وحدها لا تكفي. |
| **لا ادعاءات غير مثبتة** | كل ادعاء يجب أن يكون مدعوماً بدليل في السياق. لا `"أنجزت مئات المشاريع"` بلا أرقام. الأرقام المحددة > الأرقام الضخمة. |
| **التخصص على العمومية** | `"Node.js API design with JWT + refresh token rotation"` > `"تطوير واجهات برمجية آمنة"`. |
| **لا مبالغة بالأرقام** | `"60% reduction in latency"` يفوق `"reduced latency significantly"` في المصداقية — حتى لو الرقم أصغر. |

---

## ثالثاً: قواعد الكثافة المعلوماتية

الجمهور المستهدف: principal يعمل بـ budget authority وliteracy تقني عالٍ. لا يُبسَّط المحتوى لجمهور عام.

> المبدأ الموجه من الدستور (Section 4.3): *"Information density must match evaluator sophistication — not be simplified for generic audiences."*

| ✓ مسموح — كثيف وتقني | ✗ محظور — مبسط زائداً |
|----------------------|----------------------|
| *"SSR with ISR fallback on Next.js, edge-cached via Vercel CDN"* | *"موقع سريع التحميل باستخدام أحدث التقنيات"* |
| *"Token-based design system with 8pt grid and CSS custom properties"* | *"تصميم منظم ومتناسق"* |

---

## رابعاً: قواعد الإيقاع والـ Whitespace

| القاعدة | التطبيق |
|---------|---------|
| **الفقرات قصيرة** | 3 جمل بحد أقصى للفقرة الواحدة. إذا احتجت 4، اقسمها. الاستثناء الوحيد: Case Study. |
| **Whitespace هو تعبير** | المساحة الفارغة ليست فراغاً — هي إعلان عن الضبط الذاتي. الموقع الكثيف بصرياً يعني التاجر. الموقع المتنفس يعني الشريك. |
| **لا حشو تجميلي** | لا جمل انتقالية فارغة كـ `"يسعدني أن أشاركك..."` أو `"أخيراً وليس آخراً"`. ابدأ بالمعلومة. |
| **البنية تحل محل التشويق** | لا مقدمات، لا مطولات. الهرم المعكوس — الفكرة الرئيسية أولاً، التفاصيل بعدها. |

---

## خامساً: الفرق بين النص الإنجليزي والنص العربي في النبرة

| النص الإنجليزي | النص العربي |
|----------------|-------------|
| Precision-first: direct, no softening | يُسمح بمرونة طفيفة في البنية — اللغة العربية أغنى تركيبياً |
| No diacritics, no formal Classical Arabic | نبرة فصيحة معاصرة — لا عامية، لا تكلف مصطنع |
| Technical terms stay in English | المصطلحات التقنية بالإنجليزية دائماً، بلا ترجمة |
| Minimal punctuation used for rhythm | الإيقاع يُبنى على البنية لا الترقيم المفرط |
| No rhetorical questions | لا أسئلة بلاغية. كلا اللغتين: تصريحات لا استفهامات. |

# المهمة الثالثة — اختيار الخطوط وأوزانها

> القانون المرجعي من `Section XII.2`: *"Maximum two typefaces — one serif or geometric sans for headings; one legible sans for body."*
>
> جميع الخطوط متاحة مجاناً على **Google Fonts** — متوافق مع Phase 1 constraint.

---

## أ) خط اللغة الإنجليزية

### الخط الرئيسي للعناوين: DM Sans

| المحور | التفاصيل |
|--------|-----------|
| **لماذا DM Sans؟** | خط geometric sans-serif مصمم أصلاً للـ digital screens. هندسته النظيفة تعكس مباشرةً مبدأ "Precision" في Brand Cognitive Model. لا زخرفة. لا تعرجات عاطفية. قوسه الهندسي في حرف `O` يعكس الـ systematic thinking الذي يُعرّف به عامر في Core Identity Matrix. |
| **الارتباط بالدستور** | `"Typographic authority"` (Section III.1) + `"Discipline"` كـ brand attribute. DM Sans يُجسّد هذا بصرياً: حازم، غير مُزخرف، واضح الهيكل. |
| **يجتاز اختبار الـ Filter** | *"هل يُعزز السلطة ويُصفّي العميق غير المناسب؟"* — نعم. DM Sans يُرسل إشارة تقنية-احترافية لا إشارة مبدع/فنان. |

### خط النص الأساسي: Inter

| المحور | التفاصيل |
|--------|-----------|
| **لماذا Inter؟** | صُمم خصيصاً لشاشات الكمبيوتر. أفضل legibility على الـ dark mode (المتطلب الأساسي في Section XII.2). وضوح استثنائي عند الأحجام الصغيرة. يتوافق بصرياً مع DM Sans في الشخصية الهندسية. |
| **الارتباط بالدستور** | `"Legible sans for body"` (Section XII.2) + `"Respect for evaluator's time"` (Section III.3). قراءة سهلة = احترام للمُقيِّم. |

---

## ب) خط اللغة العربية

### خط العناوين العربية: Cairo

Cairo هو الخيار الأعلى توافقاً بصرياً مع DM Sans من بين خطوط Google Fonts العربية. كلاهما geometric، كلاهما يعتمد على الأشكال الدائرية النظيفة، وكلاهما يحمل شخصية تقنية-احترافية لا فنية-زخرفية. الوزن البصري في Cairo Bold يُعادل تقريباً DM Sans Bold، مما يحقق التماسك العابر للغتين.

> الارتباط بالدستور: مبدأ `"Visual consistency heuristic"` (Section IV.4) — الاختلاف البصري بين اللغتين يُسجَّل كتناقض وإهمال. Cairo يحل هذه المشكلة.

### خط النص العربي الأساسي: IBM Plex Arabic

IBM Plex Arabic هو خط مصمم بمعايير corporate-technical مماثلة لـ Inter. وضوح استثنائي عند الأحجام الصغيرة، حركات غير لازمة، ويتوافق مع Inter في الإيقاع التقني.

> بديل مقبول إذا تعذر: **Noto Sans Arabic** — لكن IBM Plex يتفوق في الشخصية.

## ج) منظومة الأوزان

> القانون: لا يتجاوز عدد الأوزان **4 أوزان** لكل خط (Section XII.2 — visual restraint).

| الوزن | الاستخدام | المبرر من الدستور |
|-------|-----------|-------------------|
| **300 Light** | النص الثانوي، labels، captions، metadata التواريخ والتصنيفات | `"Visual restraint"` — الوزن الخفيف يعزز الهدوء البصري لا يقلل الأهمية |
| **400 Regular** | Body text، محتوى الـ Case Study، وصف المشاريع | `"Legibility"` كـ trust signal — النص المريح يُبقي المُقيِّم منخرطاً |
| **600 SemiBold** | عناوين الأقسام الفرعية (H2/H3)، التأكيد الانتقائي، أسماء التقنيات | يُميز التسلسل الهرمي دون صراخ. Discipline بصري. |
| **700 Bold** | العناوين الرئيسية فقط (H1، Display)، Hero headline | `"Typographic authority"` — التأثير يأتي من الندرة، لا من الاستخدام المكثف |

# المهمة الرابعة — مقياس التايبوغرافيا (Type Scale)

> المبدأ الدستوري: *"Strict 5-step type scale"* (Section XII.2).  
> تم توسيعه إلى 6 مستويات لاستيعاب الـ Display كمستوى مستقل عن H1.  
> النسبة المستخدمة: **1.25 modular scale** (Major Third).

| المستوى | الحجم (px) | CSS `font-size` | الاستخدام | المبرر من الدستور |
|---------|-----------|-----------------|-----------|-------------------|
| **Display** | 48–56px | `3rem–3.5rem` | Hero headline — الجملة الأولى في الموقع | `"Typographic authority"` — Impact without noise |
| **H1** | 36px | `2.25rem` | عناوين الصفحات الرئيسية | Single H1 per page (Section VIII.2) |
| **H2** | 28px | `1.75rem` | عناوين الأقسام الرئيسية داخل الصفحة | Information hierarchy — evaluator navigation |
| **H3** | 22px | `1.375rem` | عناوين الفقرات، sub-sections | Progressive disclosure (Section IV.3) |
| **Body** | 16px | `1rem` | النص الأساسي، محتوى Case Study، Approach | Optimal reading size for screen — legibility signal |
| **Caption** | 12–13px | `0.75rem–0.8rem` | Labels، metadata، أسماء التقنيات، timestamps | `"Tight grid"` (Section XII.2) — data precision |

---

## قواعد التسلسل الهرمي الإضافية

| القانون | السبب |
|---------|-------|
| **H1 واحد فقط لكل صفحة** | مطلب دستوري صريح (Section VIII.2) ومطلب SEO. |
| **لا تخطي مستويات** | لا تنتقل من H1 مباشرة إلى H3. التسلسل المنطقي جزء من `"Structural clarity"`. |
| **Display للـ Hero فقط** | استخدامه في أي مكان آخر يُفقده قيمته كإشارة سلطة. الندرة هي القوة. |
| **Line Height: 1.5–1.6 للـ Body** | 8pt grid baseline (Section XII.2). عند 16px: `line-height: 1.5` = 24px. |
| **Letter Spacing على الـ Display** | `-0.02em` إلى `-0.03em` على العناوين الكبيرة لتعزيز الكثافة. |

## CSS Variables Reference

```css
/* === AMER Typography Token System === */
/* Section XII.2 — All values via :root, never ad hoc */

:root {
  /* Fonts */
  --font-heading-en: 'DM Sans', sans-serif;
  --font-body-en:    'Inter', sans-serif;
  --font-heading-ar: 'Cairo', sans-serif;
  --font-body-ar:    'IBM Plex Arabic', sans-serif;

  /* Type Scale */
  --font-size-display: clamp(2.5rem, 5vw, 3.5rem); /* 40–56px */
  --font-size-h1:      2.25rem;   /* 36px */
  --font-size-h2:      1.75rem;   /* 28px */
  --font-size-h3:      1.375rem;  /* 22px */
  --font-size-body:    1rem;      /* 16px */
  --font-size-caption: 0.8rem;    /* 13px */

  /* Weights */
  --font-weight-light:    300;
  --font-weight-regular:  400;
  --font-weight-semibold: 600;
  --font-weight-bold:     700;

  /* Line Heights */
  --line-height-display: 1.1;
  --line-height-heading: 1.25;
  --line-height-body:    1.6;
  --line-height-caption: 1.4;

  /* Letter Spacing */
  --letter-spacing-display: -0.025em;
  --letter-spacing-heading: -0.01em;
  --letter-spacing-body:     0;
  --letter-spacing-caption:  0.02em;
}
```

# ملاحظات ختامية — التعارضات المحتملة وحلولها

| التعارض | طرفا التعارض | الحل |
|---------|--------------|------|
| **Notes تتيح نبرة شخصية، لكن قاعدة "لا تودد مصطنع" تسري على الكل** | انفتاح Notes ← قواعد الصوت العامة | Notes تُجيز الشخصية الفكرية (رأي، نقد، تحليل) دون التودد العاطفي. الفرق: *"أعتقد أن الـ framework يُشوش القرار المعماري"* مقبول. *"أتمنى أن يستمتع القراء بهذا!"* محظور. |
| **الكثافة التقنية مطلوبة لكن Case Study أطول من باقي الصفحات** | `"No more than 3 paragraphs per section"` ← depth في Case Study | *"Max 3 paragraphs"* ينطبق على sections داخل Case Study، لا على Case Study كصفحة. الصفحة يمكن أن تحتوي أقساماً متعددة بلا تعارض. |
| **Display مقيد بالـ Hero فقط، لكن الـ Notes قد تحتاج impact** | ندرة Display ← احتياجات Notes | في Notes، يكفي H1 + Letter Spacing لتأسيس الثقل. Display محجوز للـ Homepage Hero. التسوية: استخدام `--font-size-h1` + `letter-spacing: -0.02em` في Notes لتعزيز الأثر بدون كسر القانون. |
