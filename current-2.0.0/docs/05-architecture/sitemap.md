# 🗺️ sitemap.md — خريطة الموقع

> "قبل أن تبني صفحة، حدد لماذا تستحق الوجود."

---

## 1️⃣ مبدأ البناء

الموقع لا يُبنى بمنطق "كل موقع يحتاج هذه الصفحات". يُبنى بمنطق:

> **كل صفحة تؤدي وظيفة في رحلة الثقة — أو لا توجد.**

الهيكل التالي مبني على تسلسل نموذج الثقة من `user-journey.md`:
`صلة → مصداقية → شخصية → دليل → فعل`

كل صفحة تخدم مرحلة في هذا التسلسل.

---

## 2️⃣ الهيكل الكامل — نظرة عليا

```
/  (Homepage)
├── /work                    ← معرض الأعمال
│   └── /work/[project-slug] ← دراسة حالة مفردة
├── /about                   ← من أنا؟
├── /contact                 ← تواصل
└── /blog  (مرحلة 2)        ← محتوى ومقالات — غير مفعّل في البداية
    └── /blog/[post-slug]    ← مقال مفرد
```

## 3️⃣ الصفحات — تفصيل لكل مسار

---

### `/` — الصفحة الرئيسية

```
النوع:      صفحة رئيسية (Landing + Navigation hub)
الأولوية:   🔴 الأعلى — نقطة الدخول لكل زيارة
الهدف:      بناء الثقة الكافية لتحفيز خطوة التواصل أو استكشاف الأعمال
```

**ما تفعله:**
- تثبيت الصورة الذهنية خلال 5 ثوانٍ
- تصفية العميل غير المناسب بشكل ضمني
- توجيه الزائر المناسب نحو `work/` أو `contact/`

**ما لا تفعله:**
- لا تعرض كل الأعمال — مختارات فقط
- لا تكون صفحة "عن" — بل تُلمح إليها
- لا تُغلق الصفقة — تفتح الحوار

---

### `/work` — صفحة الأعمال

```
النوع:      معرض مُصفّى (Curated Portfolio)
الأولوية:   🔴 عالية — الدليل الرئيسي على القدرة
الهدف:      إثبات القدرة بالدليل — لا بالادعاء
```

**ما تفعله:**
- عرض مشاريع مختارة بعناية تعكس نوع العمل المطلوب
- كل مشروع بعنوان + تصنيف + مختصر وصفي
- الضغط على مشروع → `/work/[slug]`

**معيار ما يُعرض:**
```
✅ يعكس نوع المشاريع التي نريد استقطابها
✅ يُظهر تفكيراً حقيقياً لا مجرد تنفيذ
✅ السياق موجود: المشكلة + القرار + النتيجة
❌ كل مشروع عملنا عليه
❌ مشاريع لا تخدم التموضع المطلوب
```

---

### `/work/[project-slug]` — دراسة حالة

```
النوع:      صفحة محتوى معمّق (Case Study)
الأولوية:   🟡 متوسطة-عالية — للزائر الجاد
الهدف:      تحويل الاهتمام إلى اقتناع
```

**ما تفعله:**
- تروي قصة المشروع كاملة: التحدي، القرارات، النتيجة
- تُظهر طريقة التفكير الهندسي
- تُنهي بـ CTA طبيعي: "مشروع مشابه؟ تحدث معنا"

**الوصول إليها:**
- من `/work` عبر الضغط على المشروع
- من `/` عبر مشاريع الـ Homepage المختارة
- مباشرة من رابط مشارك

---

### `/about` — صفحة عن

```
النوع:      صفحة هوية شخصية (Personal Brand)
الأولوية:   🟡 متوسطة — للزائر الذي يريد معرفة من يتعامل معه
الهدف:      بناء الألفة والثقة الشخصية
```

**ما تفعله:**
- تُظهر طريقة التفكير لا السيرة الذاتية
- تُثبت وجود شخص حقيقي وراء الكود
- تُوضّح القيم التي تُحدد طبيعة التعامل
- تنتهي بـ CTA نحو `/contact`

**ما لا تفعله:**
- لا تكون قائمة تقنيات
- لا "أنا شغوف بالبرمجة"
- لا سيرة ذاتية تسلسلية

---

### `/contact` — صفحة التواصل

```
النوع:      صفحة تحويل (Conversion Page)
الأولوية:   🔴 عالية — نقطة النهاية في كل مسار
الهدف:      تحويل النية إلى خطوة فعلية بأقل احتكاك
```

**ما تفعله:**
- نموذج تواصل بسيط: الاسم، البريد، وصف موجز للمشروع
- إدارة التوقعات: متى يرد؟ كيف تسير الخطوات التالية؟
- تصفية أخيرة: نص يذكّر بنوع المشاريع التي نعمل عليها

**ما لا تفعله:**
- لا حقول كثيرة غير ضرورية
- لا "اشترك في القائمة البريدية" هنا
- لا إعادة توجيه لصفحة شكر معقدة

---

### `/blog` — المدونة *(مرحلة 2)*

```
النوع:      منصة محتوى (Content Platform)
الأولوية:   ⚪ منخفضة حالياً — مرحلة مستقبلية
الهدف:      بناء سلطة تقنية + جذب زوار عضويين
```

**متى تُفعَّل؟**

## 4️⃣ التنقل — Navigation Structure

### الـ Navbar (Primary Navigation):

```
Logo/Name    |    Work    About    Contact
```

**القواعد:**
- بسيط — لا Mega Menu، لا قوائم منسدلة في المرحلة الأولى
- Logo يرجع لـ `/` دائماً
- Active state واضح للصفحة الحالية
- على Mobile: Hamburger يكشف القائمة بـ overlay بسيط

### الـ Footer (Secondary Navigation):

```
[Name / Tagline]

Work    About    Contact    Blog*

[بريد إلكتروني مباشر]
[LinkedIn]  [GitHub]  (روابط اجتماعية محدودة)

© 2025 — مبني بعناية.
```

## 5️⃣ تسلسل الأولوية في البناء

```
المرحلة 1 (إطلاق):
  1.  /           — الصفحة الرئيسية
  2.  /work       — صفحة الأعمال (مشاريع أولية)
  3.  /contact    — صفحة التواصل
  4.  /about      — صفحة عن

المرحلة 2 (توسعة):
  5.  /work/[slug]  — دراسات الحالة التفصيلية
  6.  /blog         — المدونة
  7.  /blog/[slug]  — مقالات مفردة
```

> [!NOTE]
> الإطلاق الأول لا يحتاج دراسات حالة كاملة. يكفي `/work` بعرض Cards مع وصف موجز وصورة. دراسات الحالة تُضاف تدريجياً.

## 6️⃣ الـ URLs — منطق التسمية

```
القاعدة: URLs واضحة، قصيرة، وصفية — لا رقمية، لا hashes

/work/saas-dashboard-redesign    ✅ وصفي وواضح
/work/project-3                  ❌ لا معنى له
/work/2024-client-saas-proj-v2   ❌ طويل ومعقد
```

**قاعدة Slug:**
- حروف صغيرة فقط
- كلمات مفصولة بـ `-`
- بدون أحرف خاصة أو أرقام عشوائية
- الكلمات تصف المشروع لا اسم العميل (خصوصية)
