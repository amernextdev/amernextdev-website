# risk-landscape.md

## الهدف
تسمية أوضاع الفشل المحتملة في المنظومة وتحديد آلية الكشف والاستجابة لكل منها.
التسمية المسبقة تُتيح رفضاً أسرع وتدخلاً أبكر.

## المشمول
- أوضاع الفشل على مستوى الهوية والتموضع
- أوضاع الفشل على مستوى التقنية والمعمارية
- أوضاع الفشل على مستوى المحتوى واللغة
- إشارات الكشف المبكر لكل وضع
- الاستجابة المطلوبة

## غير المشمول
- آلية حسم التعارض بين مبدأين (→ `conflict-resolution.md`)
- بروتوكول القرار اليومي (→ `decision-engine.md`)
- بروتوكولات التشغيل والمراجعة الدورية (→ `06-operations/`)

## أوضاع فشل الهوية والتموضع

### R1 — الانجراف نحو Portfolio النمطي
**التعريف:** تراكم قرارات صغيرة تُحوّل الموقع تدريجياً إلى معرض أعمال تقليدي.
**إشارات الكشف:**
- ظهور قسم "عن نفسي" بلغة شخصية غير مهنية
- إضافة صور شخصية غير رسمية
- تخفيف كثافة المعلومات لتناسب جمهوراً أوسع
- أي لغة تُلمح إلى التوافر والاستعداد للجميع

**الاستجابة:** مراجعة فورية بـ `decision-engine.md` بوابة 3. إزالة العناصر المُنجرفة.

---

### R2 — تخفيف آلية التصفية
**التعريف:** إضافة عناصر تُزيل الحواجز المقصودة أمام العملاء غير المؤهلين.
**إشارات الكشف:**
- أي إشارة للأسعار أو نطاقاتها
- نموذج تواصل مفتوح بدون تأهيل مسبق
- لغة CTA ذات جاذبية جماهيرية ("تواصل الآن"، "احجز استشارة مجانية")
- ذكر التوافر الفوري

**الاستجابة:** رفض فوري. العناصر لا تُعدَّل — تُحذف.

---

### R3 — تآكل السلطة اللغوية
**التعريف:** انزلاق تدريجي في لغة المحتوى نحو التحمس أو الغموض.
**إشارات الكشف:**
- صفات تفضيل عليا ("متميز"، "استثنائي"، "رائد")
- ادعاءات عامة غير قابلة للتحقق ("أبني تطبيقات عصرية")
- جمل مبنية للمجهول تُبهم الفاعلية
- نبرة متلهفة في أي موضع

**الاستجابة:** مراجعة كل المحتوى بـ `language-governance.md`. إعادة كتابة وفق القوانين L1–L4.

## أوضاع فشل التقنية والمعمارية

### R4 — تراكم الدين التقني
**التعريف:** تراكم قرارات تنفيذية تُعقّد الهجرة إلى المرحلة الثالثة دون أن تُدرَج في سجل.
**إشارات الكشف:**
- محتوى مُشفَّر في HTML بدل JSON
- متغيرات CSS مُعرَّفة خارج كتلة `:root`
- JS يعتمد على حالة عامة ضمنية
- اقترانات CSS عابرة للمكونات

**الاستجابة:** جلسة إصلاح مخصصة قبل أي ميزة جديدة. التوثيق في `git-workflow.md`.

---

### R5 — انتهاك ميزانية الأداء
**التعريف:** تجاوز أحد سقوف الأداء المحددة في `performance-budget.md`.
**إشارات الكشف:**
- Lighthouse score أقل من الحد الأدنى المحدد
- أي JS يعيق العرض
- صور بدون أبعاد صريحة أو تحميل كسول
- تبعية CDN جديدة غير مبررة

**الاستجابة:** لا نشر قبل استعادة الميزانية. الميزة المسببة تُؤجَّل أو تُعاد هندستها.

---

### R6 — اختراق معيار العزل
**التعريف:** مكوّن UI لم يعد قابلاً للاستخراج كـ React component مستقل.
**إشارات الكشف:**
- CSS مكوّن يعتمد على سياق مكوّن آخر
- ربط مباشر بـ DOM بين وحدتين
- محتوى الوحدة مُشفَّر لا مصدره JSON

**الاستجابة:** إعادة هيكلة قبل انتهاء المرحلة الأولى. التوثيق في `component-isolation-standard.md`.

## أوضاع فشل المحتوى

### R7 — محتوى يتيم
**التعريف:** قسم أو عنصر محتوى لا يُجيب على سؤال محدد للمقيّم.
**إشارات الكشف:**
- محتوى موجود "لأنه يبدو جيداً" لا لأنه يُجيب على شيء
- أي قسم لا يمكن ربطه بمرحلة من مراحل تقييم العميل (0–3 ث، 3–30 ث، 30+ ث)

**الاستجابة:** تعديل ليُجيب على سؤال محدد، أو حذف.

---

### R8 — تضخم الصفحة
**التعريف:** الصفحة تتجاوز الحد الأمثل للكثافة المعلوماتية للمقيّم المستهدف.
**إشارات الكشف:**
- معدل التمرير يُشير إلى نقطة تخلٍّ مبكرة (عند توفر بيانات)
- محتوى مكرر يُغطي نفس سؤال المقيّم مرتين
- أقسام يمكن دمجها دون فقد معلومة

**الاستجابة:** مراجعة `client-psychology-model.md`. حذف أو دمج.

## القيود التي يجب مراعاتها

- الأوضاع لا تُرتَّب بالخطورة — كلها ترقى لتدخل فوري عند الكشف

## التأثير على التطبيق
وجود هذه الوثيقة يجعل المراجعة الدورية منظمة: كل جلسة تفحص الموقع والكود بحثاً عن إشارات الكشف المحددة هنا.
الكشف المبكر يُقلل تكلفة الإصلاح.
