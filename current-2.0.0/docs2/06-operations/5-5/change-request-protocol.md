# change-request-protocol.md

## الهدف
تحديد البروتوكول الذي يمر به أي تغيير مقترح بعد الإطلاق — من الفكرة إلى التنفيذ إلى التوثيق.

## المشمول
- تصنيف التغييرات حسب الحجم والخطورة
- مسار كل نوع تغيير
- قالب توثيق القرارات
- معيار الدمج والنشر

## غير المشمول
- بروتوكول قرار ما إذا كان التغيير مقبولاً (→ `decision-engine.md`)
- تفاصيل النشر التقني (→ `launch-checklist.md` المراحل ج-و)
- إصدارات الـ releases (→ `release-versioning.md`)

## تصنيف التغييرات

### النوع أ — تحديث محتوى (بدون تغيير كود)
**أمثلة:** إضافة مشروع لـ portfolio.json، تعديل نص في profile.json، تحديث بيانات config.

**المسار:**
1. تعديل ملف JSON
2. فحص: لا قيمة تخالف language-governance.md
3. فحص محلي يُظهر التغيير صحيحاً
4. Commit بـ `content(data): [وصف]`
5. نشر مباشر على main

**لا يستلزم:** Lighthouse، code review، branch منفصل.

---

### النوع ب — تغيير بصري صغير (CSS فقط)
**أمثلة:** تعديل قيمة spacing، تعديل حجم خط، تعديل لون في النطاق المسموح.

**المسار:**
1. تعديل في ملف CSS أو tokens.css
2. فحص البوابة 1 من decision-engine.md (هل يخالف قانوناً؟)
3. فحص التباين إذا تغيّر لون
4. Lighthouse Accessibility و Performance (المراحل ج)
5. Commit بـ `style(component): [وصف]`
6. نشر

---

### النوع ج — ميزة جديدة أو تغيير هيكلي
**أمثلة:** إضافة قسم جديد، تغيير بنية مكوّن، إضافة تفاعل JS جديد.

**المسار:**
1. **التوثيق المسبق:** ملء قالب طلب التغيير (أدناه)
2. **تقييم:** المرور بـ decision-engine.md كاملاً
3. **Branch:** `feature/[name]` أو `refactor/[name]`
4. **التطوير** مع الالتزام بمعايير الكود
5. **Self-review** بـ checklist من git-workflow.md
6. **Lighthouse كامل** (المراحل أ-ج من launch-checklist.md)
7. **Merge + نشر**
8. **توثيق القرار** في سجل القرارات

---

### النوع د — تغيير استراتيجي
**أمثلة:** تغيير في التموضع، إعادة كتابة محتوى رئيسي، تغيير لون التأكيد، إضافة صفحة جديدة.

**المسار:**
1. **مراجعة** master-constitution.md و non-negotiable-laws.md أولاً
2. **توثيق مسبق مفصل** (قالب موسّع أدناه)
3. **تقييم التأثير** على الوثائق المرتبطة
4. **Branch:** `feature/strategic-[name]`
5. **تطوير + مراجعة كاملة**
6. **Lighthouse + accessibility كاملَين**
7. **تحديث الوثائق المتأثرة** قبل الدمج
8. **Merge + نشر + توثيق**

## قالب طلب التغيير (النوع ج)

يُحفظ في `reports/changes/[date]-[name].md`:

```markdown
## طلب تغيير — [التاريخ]

### الوصف
[ما الذي يُضاف أو يُعدَّل؟]

### السبب
[لماذا هذا التغيير مطلوب؟ ما المشكلة التي يحلها؟]

### نتيجة decision-engine.md
[ ] البوابة 1 — لا تعارض مع القوانين
[ ] البوابة 2 — لا إعاقة للهجرة
[ ] البوابة 3 — لا إضعاف للتموضع
[ ] البوابة 4 — ضمن ميزانية الأداء
[ ] البوابة 5 — التنفيذ نظيف

### التأثير التقني
[ما الملفات التي ستتغير؟ ما الوحدات المتأثرة؟]

### التأثير على قابلية الهجرة
[هل يُؤثر على أمان هجرة المرحلة الثالثة؟]

### القرار
[ ] مقبول  [ ] مرفوض  [ ] مؤجل

### المبرر
[لماذا هذا القرار؟]

### الـ Commit المرتبط
[hash أو branch name]
```

## قالب توثيق القرارات الاستراتيجية (النوع د)

```markdown
## قرار استراتيجي — [التاريخ]

### التغيير
[وصف دقيق للتغيير]

### مسوّغ التغيير
[لماذا يستحق هذا التغيير مراجعة مبادئ الدستور؟]

### البدائل المدروسة
[ما الخيارات الأخرى التي نُظر فيها؟ لماذا رُفضت؟]

### تأثيره على الوثائق
[الوثائق التي تحتاج تحديثاً نتيجة هذا القرار]

### القانون أو المبدأ المعدَّل (إن وجد)
[هل يستلزم هذا تعديل قانون في non-negotiable-laws.md؟]

### الموافقة
القرار مؤكَّد بتحديث الوثيقة المعنية في docs/
```

## تسلسل الأولوية عند تعارض طلبين

إذا كان طلبان في الانتظار وأحدهما يعارض الآخر:

1. يُقيَّم كل طلب بشكل مستقل عبر decision-engine.md
2. الطلب الذي يجتاز كل البوابات يُقدَّم
3. إذا كلاهما يجتاز — يُحسم بتراتبية conflict-resolution.md
4. إذا كلاهما يُعيق الآخر — يُؤجَّل الأقل أولوية

## القيود التي يجب مراعاتها
- لا تغيير "عاجل" يتخطى decision-engine.md. العجلة مسوّغ للتسريع لا للتخطي.
- كل تغيير نوع د يستلزم تحديث الوثيقة المتأثرة — لا تغيير استراتيجي بدون توثيق.

## التأثير على التطبيق
هذا البروتوكول يُبقي المنظومة متسقة عبر الزمن.
بدونه، التغييرات الصغيرة المتراكمة تُنجرف بالمنظومة بعيداً عن مبادئها.

## وثائق مرتبطة
- `decision-engine.md` (← `01-constitution/`) — تقييم كل تغيير
- `conflict-resolution.md` (← `01-constitution/`) — حسم التعارض
- `git-workflow.md` (← `03-technical/`) — التوثيق في Git
- `release-versioning.md` — الإصدارات المرتبطة بالتغييرات
