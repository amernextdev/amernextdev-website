# 📚 section-library.md — مكتبة الأقسام

> "القسم القابل لإعادة الاستخدام هو قرار تصميمي واحد يُصنع مرة ويُطبَّق في كل مكان."

---

## 1️⃣ فلسفة المكتبة

### لماذا مكتبة أقسام؟

بدون مكتبة: كل صفحة تُبنى من الصفر → تناقضات بصرية، قرارات متكررة، وقت ضائع.

بالمكتبة: أقسام جاهزة محكومة بنفس القواعد → سرعة في التنفيذ، اتساق في الهوية.

### التصنيف المعتمد:

```
مكتبة الأقسام
├── 1. Hero Sections         ← مداخل الصفحات
├── 2. Content Sections      ← عرض المعلومات والمحتوى
├── 3. Proof Sections        ← بناء المصداقية والدليل
├── 4. CTA Sections          ← نقاط التحويل
└── 5. Utility Sections      ← أقسام وظيفية (نموذج، Footer)
```

## 2️⃣ Hero Sections

---

### HERO-01 — Dark Full Hero

```
الاستخدام:  الصفحة الرئيسية (/)
السطح:      section--dark
الحاوية:    container-wide
الـ Grid:   Full Column
```

**الهيكل:**
```
┌─────────────────────────────────────────────────┐
│                  Section--dark                  │
│              (padding: 128px–160px)             │
│                                                 │
│   [Label — xs، signal color، uppercase]         │
│                                                 │
│   H1 Display — font-display، 3–3.75rem          │
│   (2 سطر كحد أقصى)                              │
│                                                 │
│   Lead — text-lg، muted، max-width: 560px       │
│                                                 │
│   [Ghost CTA ← نص فقط، هادئ]                   │
│                                                 │
└─────────────────────────────────────────────────┘
```

**المتغيرات:**
- `HERO-01-A`: بدون صورة — النص هو البطل
- `HERO-01-B`: مع صورة/screenshot محاذية لليمين (Grid 7/5)

**متى لا تُستخدم:**
صفحات داخلية — تبدو ثقيلة جداً خارج سياقها.

## 3️⃣ Content Sections

---

### CONTENT-01 — Value Statement (فقرة قيمة)

```
الاستخدام:  بعد Hero-01 مباشرة في الرئيسية، بداية /about
السطح:      section--light
الحاوية:    container-narrow
```

**الهيكل:**
```
نص فقرات بدون عنوان H2 بالضرورة
max-width: 640px
font-size: text-lg
line-height: leading-relaxed
```

**الغرض:** إنشاء "الصلة" مع الزائر قبل عرض أي خدمة أو عمل.

**قاعدة المحتوى:** يتكلم عن مشكلة العميل — لا عن المطور.

---

### CONTENT-02 — Steps / Process (خطوات)

```
الاستخدام:  قسم "كيف أعمل" في الرئيسية و/about
السطح:      section--dark أو section--light
الحاوية:    container-default
الـ Grid:   3-Col
```

**الهيكل:**
```
[Section Header: Label + H2 + Lead]

┌──────────┐  ┌──────────┐  ┌──────────┐
│ [رقم]   │  │ [رقم]   │  │ [رقم]   │
│ العنوان  │  │ العنوان  │  │ العنوان  │
│ الوصف   │  │ الوصف   │  │ الوصف   │
└──────────┘  └──────────┘  └──────────┘
```

**قاعدة المحتوى:** كل خطوة تُفسّر "لماذا" لا "ماذا" فقط.

---

### CONTENT-03 — Feature List (ميزات/قيم)

```
الاستخدام:  قيم العلامة، خصائص الخدمة
السطح:      section--light أو section--dark
الحاوية:    container-default
الـ Grid:   2-Col أو 3-Col
```

**الهيكل:**
```
[Section Header]

┌────────────────┐  ┌────────────────┐
│ [أيقونة بسيطة]│  │ [أيقونة بسيطة]│
│ العنوان        │  │ العنوان        │
│ وصف موجز       │  │ وصف موجز       │
└────────────────┘  └────────────────┘
```

**ملاحظات تنفيذية:**
- الأيقونات: SVG Line icons محايدة — لا أيقونات ملوّنة زخرفية
- الوصف: 2-3 جمل كحد أقصى لكل ميزة

---

### CONTENT-04 — Long Form Text (نص طويل)

```
الاستخدام:  دراسات الحالة، صفحة /about، مقالات /blog
السطح:      section--light
الحاوية:    container-narrow
```

**الهيكل:**
```
H2 (إذا لزم)
Lead (أول فقرة)
فقرات نصية — line-height: 1.7
H3 للعناوين الفرعية (إذا احتاج)
```

**قاعدة الطول:** فقرات لا تتجاوز 5-6 أسطر قبل مسافة تنفس.

---

### CONTENT-05 — Media + Text (محتوى + صورة)

```
الاستخدام:  مراحل في دراسات الحالة، /about مع صورة
السطح:      متغير
الحاوية:    container-default
الـ Grid:   8/4 أو 6/6 حسب السياق
```

**الهيكل:**
```
على Desktop:
[نص — 8 أعمدة]     [صورة — 4 أعمدة]
أو
[صورة — 6 أعمدة]    [نص — 6 أعمدة]

على Mobile: تكدّس عمودي — الصورة أسفل النص
```

**ملاحظات تنفيذية:**
- الصور دائماً بـ `alt` وصفي حقيقي
- لا صور مخزون (Stock Photos) — screenshots أو illustrations بسيطة فقط

## 4️⃣ Proof Sections

---

### PROOF-01 — Work Grid (شبكة الأعمال)

```
الاستخدام:  /work (الشبكة الكاملة)، مختارات في الرئيسية
السطح:      section--light
الحاوية:    container-default
الـ Grid:   2-Col أو 3-Col
```

**الهيكل:**
```
[Filter Tags — اختياري، يظهر عند > 6 مشاريع]

[Work Card]  [Work Card]
[Work Card]  [Work Card]
[Work Card]  [Work Card]

[Ghost CTA: "اطّلع على كل الأعمال"] ← في نسخة الرئيسية فقط
```

---

### PROOF-02 — Testimonial (شهادة)

```
الاستخدام:  بعد الأعمال في الرئيسية (إذا توفرت شهادات)
السطح:      section--dark
الحاوية:    container-narrow
```

**الهيكل:**
```
[علامة اقتباس كبيرة — زخرف وظيفي]
"نص الشهادة..."
— الاسم، الدور، الشركة
```

**قاعدة صارمة:** إما شهادة حقيقية بتفاصيل قابلة للتحقق — أو لا شهادة.

---

### PROOF-03 — Stats / Numbers (أرقام)

```
الاستخدام:  اختياري — فقط إذا كانت الأرقام تعكس القيمة الحقيقية
السطح:      section--dark
الحاوية:    container-default
الـ Grid:   3-Col أو 4-Col
```

**الهيكل:**
```
[رقم كبير: مثلاً "12"]    [وصف: "مشروع مكتمل"]
[رقم كبير: مثلاً "5+"]   [وصف: "سنوات خبرة"]
```

**تحذير:** أرقام مبالغ فيها أو بلا سياق تُسقط المصداقية. لا تُضاف إلا إذا كانت صادقة ومُضافة قيمة.

## 8️⃣ قاعدة الإضافة المستقبلية

عند إضافة قسم جديد للمكتبة:

```
1. حدد الاسم: [CATEGORY]-[رقم]
2. وثّق: الاستخدام + السطح + الحاوية + الشبكة
3. ارسم الهيكل النصي أولاً قبل التنفيذ
4. حدد متغيراته (A، B، C)
5. أضفه لجدول التوزيع
6. لا تخترع قسماً لأعجبك بصرياً — بل لأنه يؤدي وظيفة محددة
```
