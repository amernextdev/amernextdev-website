# 📋 page-blueprints.md — تشريح الصفحات

> "كل صفحة هي قصة — لها بداية تجذب، وسط يُقنع، ونهاية تدفع للفعل."

---

## 1️⃣ كيف نقرأ هذا الملف

كل صفحة موثّقة بنفس الهيكل:

```
اسم القسم
├── الهدف: ماذا يفعل هذا القسم؟
├── المحتوى: ما الذي يجب أن يظهر فيه؟
├── المكوّن: ما الـ Section type المستخدم؟
└── ملاحظة تنفيذية: قرارات لا تُفوَّت
```

هذا المستند هو **المرجع التنفيذي** — يُترجم كل ما سبق في `strategy/` و`brand/` و`ux-ui/` إلى قرارات صفحة فعلية.

---

## 2️⃣ الصفحة الرئيسية — `/`

> الهدف الكلي: تحويل الغريب إلى مهتم خلال 60 ثانية.

---

### القسم 1 — Hero

```
الهدف:     الانطباع الأول + تثبيت الصورة الذهنية + CTA أولي
السطح:     داكن (section--dark)
الحاوية:   container-wide
```

**المحتوى:**
```
┌──────────────────────────────────────────────┐
│  [Label صغير: "مطور حلول رقمية" أو تصنيف]  │
│                                              │
│  H1 — العنوان الرئيسي                       │
│  (الرسالة الجوهرية — راجع hero-messages.md) │
│                                              │
│  Lead — فقرة فرعية: 2-3 جمل تُوضّح         │
│  من هو؟ لمن يعمل؟ وما الفرق؟               │
│                                              │
│  [CTA ثانوي هادئ: "اطّلع على الأعمال ↓"]   │
└──────────────────────────────────────────────┘
```

**ملاحظات تنفيذية:**
- H1 يستخدم `--font-display` (Fraunces) للتمايز البصري
- لا صورة شخصية في الـ Hero — التصميم يتكلم بدلاً منها
- CTA هادئ: رابط نصي أو زر Ghost — ليس Primary Button ضخم
- لا Tagline من نوع "أهلاً بكم في موقعي"

---

### القسم 2 — Value Proposition (الوعد)

```
الهدف:     الإجابة على "هل هذا الشخص يفهمني؟"
السطح:     فاتح (section--light)
الحاوية:   container-narrow
```

**المحتوى:**
```
3–4 جمل تتكلم عن مشكلة العميل — لا عن المطور.

مثال الأسلوب:
"معظم المشاريع الرقمية لا تفشل بسبب الكود —
تفشل بسبب غياب الفهم الكافي قبل البناء.
أعمل بمنهجية تبدأ بالمشكلة، لا بالحل."
```

**ملاحظات تنفيذية:**
- قسم قصير عمداً — بلا عنوان H2 إذا أمكن
- يُنشئ "الصلة" مع الزائر قبل أي عرض للخدمات
- النص محايد لا يُعدد تقنيات

---

### القسم 3 — How I Work (المنهجية)

```
الهدف:     إثبات أن هناك تفكيراً منهجياً — لا تنفيذاً عشوائياً
السطح:     داكن (section--dark)
الحاوية:   container-default
الشبكة:    3-Col Grid (خطوات)
```

**المحتوى:**
```
Section Label: "كيف أعمل"
H2: عنوان يصف الفلسفة لا الخطوات

3 خطوات موثّقة بـ Cards:
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│ 01. الفهم   │  │ 02. البناء  │  │ 03. التسليم │
│             │  │             │  │             │
│ وصف + لماذا│  │ وصف + لماذا│  │ وصف + لماذا│
└─────────────┘  └─────────────┘  └─────────────┘
```

**ملاحظات تنفيذية:**
- الأرقام (01، 02، 03) تُعطي إحساساً بالترتيب الهندسي
- كل خطوة تُفسّر "لماذا" لا "ماذا" فقط
- لا CTA في هذا القسم — لا يزال في مرحلة بناء الثقة

---

### القسم 4 — Selected Work (أعمال مختارة)

```
الهدف:     الانتقال من "يفهم" إلى "يقدر" — الدليل بالعمل
السطح:     فاتح (section--light)
الحاوية:   container-default
الشبكة:    2-Col Grid (مشروعان أو ثلاثة بتوزيع مدروس)
```

**المحتوى:**
```
Section Label: "من الأعمال"
H2: عنوان يُصوّب نحو النتائج

[Card 1]  ←  مشروع يعكس النوع الأول من العملاء المستهدفين
[Card 2]  ←  مشروع يعكس النوع الثاني
[Card 3؟] ←  اختياري إذا أضاف تنوعاً حقيقياً

[Ghost Button: "اطّلع على كل الأعمال →"]
```

**ملاحظات تنفيذية:**
- 2–3 مشاريع فقط — الإطار المحدود يُشعر بالتأنّي والتحرّي
- كل Card يُظهر Label التصنيف + العنوان + مختصر المشكلة/الحل
- لا "عدد مشاريع أنجزناها: ٥٠+" — يُضعف المصداقية بلا سياق

---

### القسم 5 — Social Proof (الدليل الاجتماعي)

```
الهدف:     بناء المصداقية بصوت طرف ثالث
السطح:     داكن (section--dark)
الحاوية:   container-narrow
```

**المحتوى:**
```
خيار A — إذا توفرت شهادات:
  1–2 اقتباس موجز من عملاء حقيقيين
  مع: الاسم، الدور، اسم الشركة (إذا أذن)

خيار B — بلا شهادات في البداية:
  حذف القسم كلياً — لا بديل مصطنع
  (الصدق في الغياب أقوى من الشهادة المصطنعة)
```

**ملاحظات تنفيذية:**
- شهادة واحدة حقيقية > خمس شهادات مبهمة
- لا صور Avatars مصطنعة
- لا نجوم ⭐⭐⭐⭐⭐ بلا سياق — تبدو مزيّفة

---

### القسم 6 — CTA Section (الدعوة للتواصل)

```
الهدف:     تحويل الزائر المقتنع إلى خطوة فعلية
السطح:     فاتح (section--light)
الحاوية:   container-narrow
```

**المحتوى:**
```
H2: رسالة تدعو للتواصل بنبرة هادئة — لا ضغط
    مثال: "مشروع يستحق بناءه؟ نتحدث."

Lead: جملة تُدير التوقعات
    مثال: "أبدأ بفهم ما تحتاجه قبل أي اقتراح."

[CTA Primary: "ابدأ المحادثة"]  ←  يفتح /contact
```

**ملاحظات تنفيذية:**
- هذا هو الـ CTA الرئيسي الوحيد في الصفحة
- النبرة تقول "شراكة" لا "شراء"
- لا بديل: "أو تواصل على واتساب" — يكسر الاتساق

---

### الـ Footer

```
السطح:     داكن
المحتوى:   Navigation ثانوية + بريد مباشر + روابط اجتماعية + حقوق
```

← راجع [`sitemap.md`](./sitemap.md) للتفاصيل

## 3️⃣ صفحة الأعمال — `/work`

> الهدف الكلي: تمكين الزائر من تقييم القدرة بالدليل.

---

### القسم 1 — Work Hero

```
الهدف:     تأطير الأعمال بالصورة الذهنية الصحيحة
السطح:     داكن
الحاوية:   container-narrow
```

**المحتوى:**
```
H1: جملة تصف فلسفة الأعمال
    مثال: "مشاريع بُنيت لتحل مشاكل — لا لتملأ معرضاً."

Lead: جملة واحدة تُوضّح معيار الاختيار
```

---

### القسم 2 — Projects Grid

```
الهدف:     عرض الأعمال بوضوح مع تصفية ضمنية
السطح:     فاتح
الحاوية:   container-default
الشبكة:    2-Col أو 3-Col حسب عدد المشاريع
```

**المحتوى:**
```
[Filter Tags اختياري: "كل الأعمال" | "Web App" | "Dashboard" | ...]

[Card] [Card] [Card]
[Card] [Card] [Card]

كل Card: Label + صورة + العنوان + مختصر المشكلة + رابط "التفاصيل"
```

**ملاحظات تنفيذية:**
- Filter يُضاف فقط إذا كان عدد المشاريع > 6
- ترتيب الأعمال: الأحدث أو الأكثر صلة بالتموضع — ليس بالحجم
- لا صفحات متعددة (Pagination) في المرحلة الأولى

## 4️⃣ دراسة الحالة — `/work/[slug]`

> الهدف الكلي: رواية قصة مشروع كاملة تُثبت عمق التفكير.

---

### القسم 1 — Case Study Hero

```
السطح:     داكن
المحتوى:   اسم المشروع + Label التصنيف + جملة تصف جوهر التحدي
```

---

### القسم 2 — Project Overview

```
الحاوية:   container-narrow
```

**المحتوى (جدول سريع):**

| الجانب | التفاصيل |
|---|---|
| التحدي | ما المشكلة الحقيقية؟ |
| الدور | ما الذي قُمت به تحديداً؟ |
| المدة التقريبية | أسابيع / أشهر |
| التقنيات | فقط ما يخدم فهم القرار |

---

### القسم 3 — Problem Deep Dive

```
الحاوية:   container-narrow
```

**المحتوى:**
```
- وصف المشكلة بعمق: ما السياق؟ لماذا كانت مشكلة حقيقية؟
- ما الذي جُرِّب قبلاً وفشل؟ (إذا أذن العميل)
- ما القيود التي فُرضت على الحل؟
```

---

### القسم 4 — Solution & Decisions

```
الحاوية:   container-default (لاستيعاب صور + نص)
الشبكة:    8/4 أو Full حسب المحتوى
```

**المحتوى:**
```
- القرارات التقنية والتصميمية الرئيسية
- لماذا هذا الحل وليس البديل؟ ← هنا يظهر التفكير
- صور/screenshots بسياق نصي يشرح ما يُرى
```

**ملاحظات تنفيذية:**
- الصور ليست عرضاً — كل صورة تُجيب: "ما الذي أحاول إثباته هنا؟"
- لا caption من نوع "الصفحة الرئيسية للموقع"
- Caption صحيح: "قرار التنقل المبسّط — لأن العميل المستهدف يصل من موبايل أولاً"

---

### القسم 5 — Outcome

```
الحاوية:   container-narrow
```

**المحتوى:**
```
- النتائج الموضوعية (أرقام إذا أُذن، وصف إذا لم يُؤذن)
- ما الذي كنت سأفعله بشكل مختلف؟ ← شفافية تبني ثقة
```

---

### القسم 6 — Next Project CTA

```
السطح:     داكن
```

**المحتوى:**
```
[← المشروع السابق]    [المشروع التالي →]
         
      [CTA: "مشروع مشابه؟ تحدث معنا"]
```

## 5️⃣ صفحة عن — `/about`

> الهدف الكلي: تحويل الفضول إلى ألفة.

---

### القسم 1 — About Hero

```
السطح:     داكن
الحاوية:   container-narrow
```

**المحتوى:**
```
H1: جملة تعريفية غير تقليدية
    مثال: "أفكر بطريقة هندسية — وأبني بنفس المنطق."

Lead: 2-3 جمل تُختصر طريقة التفكير
     (لا سنوات الخبرة، لا قائمة تقنيات)
```

---

### القسم 2 — Philosophy (طريقة التفكير)

```
السطح:     فاتح
الحاوية:   container-narrow
```

**المحتوى:**
```
3–5 فقرات تُجيب على:
- كيف تقترب من المشاكل؟
- ما الذي تُقدّمه على غيره في أي مشروع؟
- ما الذي لن تتنازل عنه مهما كان الضغط؟
```

**ملاحظات تنفيذية:**
- الأسلوب شخصي مباشر — بصيغة المتكلم المفرد
- لا قائمة نقاط — فقرات متصلة تُظهر التفكير
- أصعب محتوى في الموقع لكنه الأهم لبناء الثقة الشخصية

---

### القسم 3 — Skills بسياق (لا قائمة)

```
السطح:     داكن
الحاوية:   container-default
```

**المحتوى:**
```
لا:  React | Node.js | TypeScript | PostgreSQL | Docker...
نعم:
"أختار التقنية بناءً على المشكلة — لا بناءً على ما هو رائج.
في معظم مشاريع الويب أعمل بـ [X و Y] لأنهما يُتيحان [الميزة المحددة].
عندما تحتاج المشكلة غير ذلك، أتعلم ما يلزم."
```

---

### القسم 4 — CTA نحو التواصل

```
السطح:     فاتح
الحاوية:   container-narrow
```

**المحتوى:**
```
H2: دعوة للتحدث — نبرة هادئة
[CTA Primary: "تحدث معي"]
```

## 6️⃣ صفحة التواصل — `/contact`

> الهدف الكلي: أقل احتكاك ممكن من النية إلى الإرسال.

---

### القسم 1 — Contact Hero

```
السطح:     داكن
الحاوية:   container-narrow
```

**المحتوى:**
```
H1: جملة ترحيبية هادئة
    مثال: "لديك مشروع يستحق التفكير فيه؟"

Lead: إدارة التوقعات
    "أرد على كل رسالة خلال 24–48 ساعة.
     أبدأ بفهم ما تحتاجه قبل أي اقتراح."
```

---

### القسم 2 — Contact Form

```
السطح:     فاتح
الحاوية:   container-narrow
```

**حقول النموذج (3 فقط):**

```html
[الاسم]           ← نص حر، مطلوب
[البريد الإلكتروني] ← email، مطلوب
[اختصار مشروعك]   ← textarea، اختياري
                     placeholder: "ما التحدي الذي تواجهه؟"

[زر: "أرسل الرسالة"]
```

**ما بعد الإرسال:**
```
رسالة نجاح inline (لا redirect):
"وصلت رسالتك — سأرد خلال 24 ساعة."
```

**ملاحظات تنفيذية:**
- لا Captcha معقد — يزيد الاحتكاك بلا قيمة عملية ملموسة
- لا حقول: الميزانية، الجدول الزمني، كيف عرفت عني (لاحقاً)
- Textarea اختياري — يُقلل الحاجز النفسي للإرسال

---

### القسم 3 — Alternative Contact (اختياري)

```
السطح:     فاتح (ضمن نفس القسم)
```

**المحتوى:**
```
أو تواصل مباشرة:
[email@domain.com]   [أيقونة LinkedIn]
```
